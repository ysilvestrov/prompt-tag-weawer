## Висновки для плану обв'язки (клієнтський PWA)

1. **Модифікація стартової категорії при додаванні елемента (`→ обв'язка`):** якщо користувач у гостьовому режимі додає новий елемент у стартову демо-категорію, в якої `updatedAt === 0`, клієнтське сховище `src/client/storage.ts` має піднімати `category.updatedAt = now` (і додавати категорію до `dirtyCategoryIds`), щоб ця категорія вважалася активно використовуваною користувачем при злитті з акаунтом.
2. **Пакетування `dirty`-черги по 500 записів (`→ обв'язка`):** `src/client/sync-client.ts` має ділити сумарний масив `dirty` категорій, елементів і шаблонів на пакети до `LIMITS.clientSyncChunkSize` (500) записів (спочатку категорії, потім елементи, потім шаблони, щоб батьківські категорії завжди йшли перед дочірніми елементами) і оновлювати локальний стан авторитетними записами з кожної відповіді `POST /api/sync`.
3. **Захист несинхронізованих правок при зміні `userId` або `Log Out` (`→ обв'язка`):** `src/client/storage.ts` та UI мають явно перевіряти наявність непорожніх `dirtyCategoryIds` / `dirtyElementIds` / `dirtyTemplateIds` перед очищенням стану при `Log Out` та при виявленні іншого `user.id !== state.ownerUserId` (коли `state.ownerUserId !== null`), показуючи модальне вікно підтвердження.
