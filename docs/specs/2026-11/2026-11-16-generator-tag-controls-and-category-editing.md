# Розширене керування тегами в генераторі та покращене редагування категорій і елементів

Дата: 2026-11-16
Статус: чернетка
Spec-review: очікується

## Для власника

**Мета.** Спростити навігацію та вибір серед великої кількості елементів у генераторі промптів (пошук, згортання в один рядок, сортування) та прискорити наповнення бібліотеки у вкладці категорій (перехід зі скролом із генератора, фільтрація списків та багаторядкове редагування значень промптів).

**Що зміниться для тебе.**
- У блоках категорійних тегів на сторінці генератора з'являється компактне поле швидкого пошуку (`Search elements...`). При введенні тексту миттєво відфільтровуються лише ті кнопки-елементи, чия назва (`label`) або значення (`value`) містять пошуковий рядок. Якщо елемент був попередньо вибраний, а потім прихований фільтром, його вибір зберігається у зібраному промпті.
- Для кожного блоку тегу в генераторі з'являється кнопка-іконка згортання/розгортання: у згорнутому стані кнопки елементів розташовуються в один горизонтальний скрольований рядок, не розтягуючи екран по вертикалі; у розгорнутому стані (за замовчуванням) показуються всі елементи плиткою у кілька рядків.
- Додається кнопка вибору порядку відображення елементів у блоці: за замовчуванням (ручний порядок `sortOrder, id`), за алфавітом (А → Я / A → Z), за алфавітом у зворотному напрямку (Я → А / Z → A), за датою зміни (спочатку новіші), за датою зміни (спочатку старіші). При цьому в режимі `multi` обчислений промпт за правилом специфікації продовжує детерміновано склеювати елементи за порядком збереження в категорії `(sortOrder, id)`.
- У заголовку картки тегу в генераторі з'являється кнопка швидкого переходу («Edit Category»): натискання автоматично перемикає застосунок на вкладку `Categories & Elements`, обирає відповідну категорію та плавно скролить екран до форми редагування її елементів.
- У вкладці `Categories & Elements` клік на категорію в списку автоматично скролить до розділу її елементів. Над списком категорій та над списком елементів додаються поля миттєвого пошуку/фільтрації за назвою та значенням.
- Поле введення значення елемента (`Prompt value`) як при створенні нового елемента, так і при редагуванні існуючого змінюється з однорядкового `<input>` на багаторядковий `<textarea>`. Значення зберігає та відображає переноси рядків (`\n`).
- Усі нові параметри відображення генератора (стан згортання, пошукові рядки, обраний режим сортування) зберігаються в локальному стані компонента і не вимагають міграцій чи змін формату даних у БД SQLite або у схемі двосторонньої синхронізації.

**На чому стоїть рішення.**
1. У генераторі при виборі тегу потрібні фільтр, згортання в один рядок та сортування за алфавітом і датою. `[вимога власника]`
2. У редагуванні категорій потрібен перехід до категорії зі скролом, фільтрація та багаторядковий ввід тексту елемента замість однорядкового. `[вимога власника]`
3. Поточний генератор у `src/client/App.tsx` рендерить усі елементи єдиним списком `flex flex-wrap` без можливості пошуку, сортування чи згортання, а значення елементів редагуються через `<input type="text">`. `[проба]` (П-1)
4. Схема даних, функція валідації `validateElementInput` і SQLite-база вже дозволяють зберігати в полі `value` до 10 000 символів включно з переносами рядків (`\n`), тому зміни торкаються виключно клієнтського представлення без модифікації бекенду. `[проба]` (П-2)
5. `resolveTemplateVariables` вже повертає `categoryId` для кожної розпізнаної категорії, що забезпечує прямий зв'язок між карткою генератора та категорією в сховищі. `[проба]` (П-1)
6. Сортування в генераторі має бути візуальним інструментом пошуку та вибору користувача і не повинно ламати канонічний порядок формування вихідного промпту `assemblePrompt`, закріплений у `spec.md`. `[виведення]`
7. Пошуковий фільтр у генераторі не повинен скидати вже обрані елементи, інакше користувач не зможе зібрати промпт із кількох елементів, знайдених різними пошуковими запитами. `[виведення]`

**Ключові рішення.**
1. **Збереження канонічного склеювання `assemblePrompt` за `(sortOrder, id)` при будь-якому візуальному сортуванні.** Сортування кнопок-пігулок у блоці тегу генератора керує лише черговістю відображення для зручності вибору користувачем. Сам зібраний промпт у режимі `multi` формується детерміновано за правилом `spec.md` (п. 3.3).
   - Розглянуто стандартне: сортувати підстановку в промпт відповідно до візуального порядку — відкинуто, бо це ламає стабільність зібраного промпту та суперечить затвердженій специфікації системи.
2. **Багаторядковий `<textarea>` із фіксованою мінімальною висотою та збереженням форматування.** Заміна `<input type="text">` на `<textarea>` для полів додавання та редагування елементів у `Categories & Elements` та додавання класу `whitespace-pre-wrap` до блоку перегляду значення елемента.
   - Розглянуто стандартне: rich-text / markdown редактор — відкинуто, бо сутності промптів є сирим текстом, а зайві залежності збільшують бандл.
3. **Ізольований стан відображення блоків тегів у генераторі.** Пошукові запити, прапорець згортання та режим сортування зберігаються у клієнтському стані генератора (`Record<string, ...>` за нормалізованою назвою змінної) і не засмічують базу даних та чергу синхронізації `POST /api/sync`.
   - Розглянуто стандартне: зберігати стан розгорнутості та сортування на сервері в моделі `Category` — відкинуто, бо це суто персональний UX режиму конструювання, що призвів би до надлишкового мережевого трафіку при синхронізації.
4. **Одночасний перехід між вкладками та автоскрол (`scrollIntoView`).** Кнопка переходу в картці тегу викликає зміну активної вкладки на `categories`, встановлює `selectedCategoryId` та після монтування DOM виконує `element.scrollIntoView({ behavior: 'smooth', block: 'start' })`.
   - Розглянуто стандартне: модальне вікно редагування категорії прямо всередині генератора — відкинуто, бо перевантажує мобільний екран і дублює логіку CRUD.

**Що стане гірше.**
- Збільшиться щільність інтерфейсу в картках тегів генератора: додавання поля пошуку та кнопок керування вимагає акуратної адаптивної верстки для збереження зручності на екранах смартфонів.
- Якщо користувач введе пошуковий фільтр і забуде його очистити, частина елементів буде схована з поля зору (компенсується явним індикатором кількості знайдених елементів та кнопкою швидкого скидання фільтра).

## Тіло

### 1. Проби реального коду та системи

#### Проба 1 (П-1): Структура рендерингу генератора та форми редагування елементів
У `src/client/App.tsx` (рядки 724-771):
```tsx
{resolvedVariables.map((variable) => (
  <div key={variable.normalizedName} className="rounded-xl bg-white ... p-4 ...">
    <div className="flex items-center justify-between">
      <span className="text-sm font-semibold">[{variable.rawName}]</span>
...
    {variable.kind === 'category' ? (
      <div className="flex flex-wrap gap-2">
        {variable.elements.map((el) => (
          <button key={el.id} ...>{el.label}</button>
        ))}
      </div>
```
Усі елементи рендеряться без фільтра, без сортування і без можливості згортання. Поля додавання та редагування значення елемента (рядки 981, 1011):
```tsx
<input type="text" aria-label="New element value" ... />
<input type="text" aria-label="Edit element value" ... />
```
Це обмежує користувача однорядковим полем введення.

#### Проба 2 (П-2): Підтримка переносу рядків у валідації та бекенді
Перевірка `src/shared/validation.ts`:
```ts
export function validateElementInput(
  input: { label: string; value: string },
  existingElements: readonly PromptElement[],
  editingId?: string,
): ValidationResult<{ label: string; value: string }> {
  const label = input.label.trim();
  const value = input.value.trim();
  if (value.length === 0) return { ok: false, error: 'Element value is required' };
  if (value.length > LIMITS.maxValueLength) return { ok: false, error: `...` };
  return { ok: true, data: { label, value } };
}
```
`LIMITS.maxValueLength` дорівнює 10 000. Валідація не відкидає символи `\n` і `\r`. База даних `sqlite` зберігає `value TEXT`. Отже, багаторядковий текст повністю валідний на рівні ядра та сервера.

#### Проба 3 (П-3): Запуск тестів та перевірки типів
Усі 7 тестових файлів (41 тест) проходять успішно (`npm test`), компілятор TypeScript `tsc --noEmit` повертає нульовий код завершення (`npm run typecheck`).

### 2. Архітектурні деталі реалізації

#### А. Розширення блоку тегу в Генераторі
Для кожної категорії `variable` у генераторі стан UI включає:
- `searchQuery: string` (за замовчуванням `""`).
- `isCollapsed: boolean` (за замовчуванням `false`).
- `sortMode: 'default' | 'alpha-asc' | 'alpha-desc' | 'date-desc' | 'date-asc'` (за замовчуванням `'default'`).

Логіка обробки елементів:
1. **Фільтрація:**
   ```ts
   const q = searchQuery.trim().toLowerCase();
   const filteredElements = q.length === 0
     ? variable.elements
     : variable.elements.filter((el) =>
         el.label.toLowerCase().includes(q) || el.value.toLowerCase().includes(q)
       );
   ```
2. **Сортування:**
   ```ts
   const sortedElements = [...filteredElements].sort((a, b) => {
     switch (sortMode) {
       case 'alpha-asc': return a.label.localeCompare(b.label);
       case 'alpha-desc': return b.label.localeCompare(a.label);
       case 'date-desc': return b.updatedAt - a.updatedAt;
       case 'date-asc': return a.updatedAt - b.updatedAt;
       default: return 0; // зберігає початковий порядок sortByOrderAndId
     }
   });
   ```
3. **Згортання:**
   - Якщо `isCollapsed === true`, контейнер елементів має класи `flex flex-nowrap overflow-x-auto py-1 gap-2` (один горизонтальний рядок із прокруткою).
   - Якщо `isCollapsed === false`, контейнер має класи `flex flex-wrap gap-2` (повне відображення).
4. **Перехід до категорії:**
   Кнопка в заголовку блоку:
   ```ts
   const navigateToCategory = (catId: string) => {
     setActiveTab('categories');
     setSelectedCategoryId(catId);
     setTimeout(() => {
       const el = document.getElementById(`category-card-${catId}`);
       el?.scrollIntoView({ behavior: 'smooth', block: 'start' });
     }, 50);
   };
   ```

#### Б. Покращення розділу Categories & Elements
1. **Фільтр категорій:** текстове поле над списком категорій фільтрує `activeCategories` за `cat.name.toLowerCase().includes(q)`.
2. **Фільтр елементів:** текстове поле над елементами вибраної категорії фільтрує `selectedCategoryElements` за `el.label` або `el.value`.
3. **Автоскрол до елементів:** при натисканні на картку категорії у списку виконується `scrollIntoView` до блоку елементів цієї категорії.
4. **Багаторядковий ввід (`textarea`):**
   - У формі створення елемента поле `Prompt value` стає `<textarea rows={3} ... className="w-full rounded-lg border ... p-3 text-sm" />`.
   - У формі редагування існуючого елемента поле стає `<textarea rows={3} ... />`.
   - У списку елементів значення відображається як `<div className="text-xs font-mono text-slate-500 dark:text-slate-400 whitespace-pre-wrap">{el.value}</div>`.
