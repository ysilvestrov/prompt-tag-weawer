# Prompt Tag Weaver — Специфікація системи (`spec.md`)

Цей документ є єдиним джерелом правди для поведінки **Prompt Tag Weaver** (правило 1 у `AGENTS.md`).

## 1. Огляд

**Prompt Tag Weaver** — mobile-first Progressive Web Application (PWA) для модульного конструювання AI-промптів. Користувач будує складні текстові промпти, обираючи повторно використовувані текстові елементи, згруповані в категорії, та підставляючи їх у структурні шаблони з плейсхолдерами `[Variable]`.

## 2. Доменні сутності та інваріанти

1. **Category (`Категорія`):**
   - Поля: `id` (UUID), `name` (1..120 символів після `trim`), `selectionMode` (`'single' | 'multi'`), `sortOrder` (ціле число), `updatedAt` (мс UTC, `0` для незмінених стартових демо-записів), `deletedAt` (`number | null`).
   - Серед активних категорій (`deletedAt === null`) не може існувати двох із однаковою нормалізованою назвою `name.trim().toLowerCase()`.
   - Видалення категорії (`deletedAt = t, updatedAt = t`) каскадно виставляє `deletedAt = t, updatedAt = t` усім її активним елементам. Будь-який активний елемент, чия батьківська категорія видалена або відсутня під час злиття/синхронізації, автоматично переводиться у стан tombstone.
2. **PromptElement (`Елемент`):**
   - Поля: `id` (UUID), `categoryId` (UUID категорії), `label` (1..120 символів після `trim`), `value` (1..10 000 символів для активного запису), `sortOrder` (ціле число), `updatedAt` (мс UTC), `deletedAt` (`number | null`).
3. **PromptTemplate (`Шаблон`):**
   - Поля: `id` (UUID), `name` (1..120 символів після `trim`), `content` (0..10 000 символів зі статичним текстом та тегами `[Variable]`), `sortOrder` (ціле число), `updatedAt` (мс UTC), `deletedAt` (`number | null`).
4. **Ліміти бібліотеки користувача:**
   - Максимум 100 активних категорій, 500 активних елементів та 100 активних шаблонів.
5. **Стартовий демо-набір:**
   - Створюється при першому відкритті порожнього гостьового сховища (`LocalStorage`) з детермінованими UUID та `updatedAt = 0`: категорії `Models` (`single`), `Clothing` (`multi`), `Scenes` (`single`), по 2 елементи в кожній, і шаблон `Character Portrait` (`Portrait of [Models], wearing [Clothing] in [Scenes], [Camera Angle]`).

## 3. Динамічний генератор промптів

1. **Парсинг шаблону:**
   - Розпізнаються однорівневі непорожні теги `/\[([^\[\]\r\n]+)\]/g`, де назва після `trim()` не порожня. Незакриті дужки `[`, порожні `[]` або пробільні `[   ]` трактуються як статичний текст.
   - Унікальні змінні шаблону групуються за нормалізованою назвою (`rawName.trim().toLowerCase()`) у порядку першої появи в шаблоні.
2. **Прив'язка елементів керування:**
   - Якщо існує активна категорія з тією самою нормалізованою назвою — рендериться група кнопок-перемикачів з `label` активних елементів цієї категорії (відсортованих за `(sortOrder, id)`).
   - Якщо активної категорії з такою назвою немає — рендериться текстове поле вільного вводу.
3. **Збирання промпту в реальному часі (`assemblePrompt`):**
   - Для категорії в режимі `'single'` береться `value` щонайбільше одного вибраного активного елемента (першого за порядком у категорії, якщо передано декілька ID).
   - Для категорії в режимі `'multi'` `value` усіх вибраних активних елементів у порядку `(sortOrder, id)` склеюються через `", "`.
   - Якщо в категорії нічого не вибрано або текстове поле порожнє — підставляється `""`.
   - Усі входження одного нормалізованого тегу `[Variable]` у шаблоні отримують одне й те саме обчислене значення.
   - Копіювання в один дотик (`Copy to Clipboard`) записує зібраний рядок у `navigator.clipboard.writeText` і показує підтвердження `"Copied!"`.

## 4. UI/UX та PWA

- Mobile-first інтерфейс англійською мовою з нижньою навігацією на 3 вкладки (`Generator`, `Categories & Elements`, `Templates`) та висотою інтерактивних зон дотику $\ge 48\text{px}$.
- Перемикач теми `Light` / `Dark` / `System` зі збереженням у `LocalStorage`.
- Робота офлайн через `LocalStorage` та прекеш статики Service Worker (`vite-plugin-pwa`).

## 5. Автентифікація та двостороння синхронізація

1. **Гостьовий режим:**
   - Працює повністю офлайн без реєстрації; усі сутності зберігаються в `LocalStorage` (`ownerUserId: null`).
2. **Google OAuth 2.0 (OpenID Connect):**
   - `GET /api/auth/providers`, `GET /api/auth/me`, `GET /api/auth/google`, `GET /api/auth/google/callback`, `POST /api/auth/logout`.
   - Використовує Authorization Code + PKCE (`S256`) + підписану cookie `ptw_oauth_state` і перевіряє `RS256`-підпис `id_token` за публічними JWK Google через `node:crypto`.
   - Встановлює HTTP-only cookie `ptw_session`, підписану `HMAC-SHA256` (`SESSION_SECRET`).
3. **Двостороння синхронізація (`POST /api/sync`):**
   - Правило вирішення конфліктів — Last-Write-Wins на рівні всього запису сутності за `updatedAt` (за рівного `updatedAt` перемагає tombstone `deletedAt !== null`, далі детерміноване порівняння полів).
   - Сервер обрізає клієнтські `updatedAt` і `deletedAt` зверху значенням `serverNow`.
   - Незмінені стартові демо-записи (`updatedAt === 0 && deletedAt === null`) ігноруються сервером, якщо акаунт користувача вже ініціалізований (`last_seq > 0`).
   - Канонізація одноіменних активних категорій об'єднує їх під канонічним `id`, переприв'язує як вхідні елементи із запиту, так і вже збережені на сервері елементи другої категорії (присвоюючи їм новий `server_seq`), а старий `id` переводить у tombstone.
   - Сервер повертає всі записи користувача з `server_seq > sinceSeq` у сумі з авторитетними серверними версіями всіх ID із запиту, які програли LWW або були скориговані.
   - Tombstones зберігаються безстроково. Клієнт відправляє `dirty`-чергу пакетами до 500 записів (сервер приймає до 1000 записів і 5 МБ за один запит).
   - При виході (`Log Out`) або зміні `userId` в браузері дані попереднього користувача ніколи не зливаються в чужий акаунт; якщо у попереднього користувача залишилися несинхронізовані `dirty`-правки, їх скидання вимагає явного підтвердження користувача.
